# Story Orbit

Story Orbit makes alternate watch orders, specials and immediate related titles discoverable from Cinema’s existing Story Map. Viewers can compare different numbering without accidentally changing the episode they resume or search.

## Acceptance

1. In a verified TVmaze Story Map, offer an explicit Watch order control after the show header and existing journey. Original order remains the default. An alternate list shows its provider’s edition label, season and episode number or Special, episode title, original numbering and coverage of the original catalog. Keep season/page traversal accessible, provide distinct no-data and retry states, and use one subtle entry transition only after a deliberate view change. The layout must fit a 360 px viewport and honor reduced motion. Keep provider attribution and all interaction inside the current episode guide.
2. An alternate row may only point to an exact canonical episode in the same show through the provider’s typed episode links. Detect splits over the complete fetched list before pagination. Label merged, split, mixed, incomplete and unknown mappings, preserving separately labeled canonical navigation for verified links. Only an explicit View original episode action moves focus to the canonical row, with no search. Warn at the handoff that release numbers can differ and the episode title should match. Alternate numbers never become search, history, progress, Next, airtime or playback identities. Shared Story Map progress, Follow, This Week deep links, and canonical search and resume behavior stay available.
3. Offer Related titles as an independent, explicit metadata-only view. Follow only direct Wikidata predecessor/successor claims after independently confirming the current TVmaze ID. Require exact unique TVmaze IDs for related series or an unambiguous film type and IMDb ID for films. Deduplicate direct edges, show provider wording such as Comes before or Follows without implying chronology, and omit inferred relatives. An exact series opens its canonical guide inside Cinema, with a back action to the original view and focus. An exact film opens Cinema’s metadata-only title details with an explicit search action. Failures or missing relationships remain local to this view. Visiting either view causes no plugin search, download, prepare, follow change or history mutation.
4. Cover the real TVmaze Firefly DVD opener, a split and partial Stargate list, a significant special, a fixture merge, mismatched or missing links, stale navigation, and verified TV-to-TV and TV-to-film edges. Verify disabled, empty, delayed, failed and retry cases. In a controlled native Windows test, check that selecting a Firefly DVD opener lands at the canonical S01E11 and only its explicit Watch action uses that canonical ID. Verify desktop keyboard focus, a narrow reduced-motion layout, unchanged normal Story Map and Follow, no implicit search or mutations, a full sequential regression, independent exact-source review, and the installed desktop shortcut.

## Design

- Add a lazy authenticated episode orbit route with an exact show ID and a closed set of views. Retain the existing catalog and shared two-worker TVmaze reader. The index reads only the selected show’s alternate lists. The order endpoint validates list membership first, joins the full bounded result to the same canonical catalog, then returns a page. Verify episode links as HTTPS TVmaze API origin and exact episode pathname with no query, user information, extra path or fragment. Dedupe same-row references. Keep row-level unknown and split/merge statuses distinct. Preserve unknown/nullable positions. Never guess from names, numbers or external link destinations. Bound lists, rows, bytes, work, cache and per-page payload. Positive cache is six hours and errors remain retryable.
- Resolve relationships by exact Wikidata TV Maze series ID (P8600), using structured ID lookup and rechecking that claim on the selected source entity. Read a bounded set of direct P155 and P156 item claims, then check the related items’ own stable identity claims. Never follow an arbitrary URL from provider data. No login or paid metadata dependency. Make results clear if coverage is empty or partial. Use a separate failure boundary so either provider’s slowdown leaves the other view usable. Bound time, bytes, pending work and caching. Keep provider attribution visible.
- Build a compact in-dialog view with a stable chooser, episode numbering rails, an explicit return to original and lightweight related title cards. Focus only moves after deliberate navigation. Results are generation guarded across show changes, back, view changes and close. Render a clear loading status and honor reduced-motion preferences.
- Keep episode source matching and verified-history logic canonical. Edition-specific release parsing and episode timing changes belong to a separate verification problem. Do not add a networked room, scraper key, new service or background indexing. The selected release may use an alternate number even when Cinema’s existing matcher is given a canonical number, so surface the identity comparison at the handoff and avoid offering an automatic alternate play path.

### Episode mapping and boundaries

The join is to this exact show’s canonical catalog, never a provider-wide episode lookup. The order index accepts up to 32 alternate lists. Each selected order has a 3 MiB response cap, at most 4,096 rows and up to 32 links per row. Malformed non-array payloads, duplicate row IDs or oversize lists are unavailable rather than partly trusted. The server uses the existing shared two-request TVmaze worker pool and timeout and retry handling. Eight unique orbit loads may wait at once, identical work is coalesced, and at most 32 records share a six-hour positive and 30-minute empty cache. Project the full bounded order before sending a season’s page of up to 24 entries. A season may be unknown. Coverage is distinct verified canonical IDs across the whole order over the canonical catalog’s total, including specials.

| Provider evidence on a row | Shown mapping | Original episode actions |
| --- | --- | --- |
| One distinct verified link with no other row referring to it | Original episode | One action with canonical title and number |
| Same valid link repeated within this row | Same mapping as a single link | One action, after deduplication |
| Two or more alternate rows refer to one verified original | Split episode | One action for each split row pointing to the shared original |
| One alternate row refers to two or more verified originals | Merged episodes | One separately named action per original |
| A merged row also contains an original that another row references | Split and merged | One separately named action per verified original |
| Some verified and some invalid, foreign-show, or missing IDs | Incomplete mapping plus known split/merge detail when applicable | One separately named action per verified original |
| No verified links, even when a valid-looking URL points outside the catalog | Original episode unavailable | None |

### Related titles and trust

Use the Wikidata Action API at the fixed HTTPS origin and /w/api.php path. Send a descriptive Cinema User-Agent, use no credentials or redirects, and respect 429 with a retry state. The source query searches main-space for the exact P8600 statement. Require at most three search candidates and reject a total above that cap. Recheck the exact distinct P8600 value in claims before accepting precisely one source entity. Across source and targets, ignore deprecated claims and accept normal or preferred claims only when distinct external IDs agree. Show only source-side P155/P156 edges. Do not expand target edges. Ignore self-edges and conflicting directions, and cap results to eight unique target entities. A series needs one valid exact P8600, different from the original, and no contradictory film classification. A film needs P31=Q11424 and exactly one valid IMDb title ID with no TVmaze series ID. A nonconflicting P577 year is optional. Exclude unknown classes, missing IDs, and exact-ID duplicates. Use a maximum of three sequential requests per lookup (search, source entity batch, target entity batch), a 1 MiB cap and four-second timeout per response, and a ten-second total deadline. Keep at most two independent relationship lookups in progress, coalesce duplicates and cap the six-hour positive and 30-minute empty cache at 24 records. The TVmaze order view has its own cache and failure state.

### Navigation and announcements

- The native chooser stays focused when changed. Loading, result count or empty state, and failure use a persistent polite status. Retry and page buttons keep their DOM nodes and focus when activation temporarily waits. Render paging and season controls as native buttons and select. Disable unavailable actions with semantics that preserve focus on the initiating control during an in-flight request.
- View original first checks that the current catalog still contains that exact canonical ID. Clear conflicting canonical filters, select its original season, locate its actual page, and focus the rendered canonical row. Announce the alternate/original numbering difference alongside the canonical Watch button. If the episode is missing, stay on the alternate row and announce that the guide changed. A deliberate ordinary Watch click remains required for an existing search path.
- Related-series navigation focuses the new guide heading when explicitly invoked. Save the immediately previous guide state, including the related card identity and scroll position, for an in-dialog Back. Back restores that state and focuses its originating related card after it becomes visible. Use the canonical heading as a safe fallback when the card is gone. Closing leaves normal modal focus restoration available and invalidates outstanding UI requests.
- Keep results scoped to show, view, season, page and request generation. In browser and native fixtures, cover a late response after change or close, no focus theft, exact canonical target outside the current filtered page, and stable paging at narrow width. Count source-search, prepare and qBittorrent calls and compare history and follow state until the explicit Watch action. Use fixed representative provider fixtures plus a separate live provider smoke, so the test oracle is deterministic.
