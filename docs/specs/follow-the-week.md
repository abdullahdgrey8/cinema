# Follow the Week

This Week is a personal calendar for series, Korean dramas and anime. Follow a title from its Story Map episode guide after Cinema has verified its canonical TVmaze identity. Open the calendar from Home or My List.

## Acceptance

1. Following and unfollowing are explicit, keyboard operable and immediately reflected in both places. Persist up to twelve distinct verified show IDs and basic display metadata on the device. Show a clear explanation when the limit is reached or a change cannot be saved. Reopening Windows Cinema keeps the list. Include a useful empty state and a way to open a followed show's guide when it has no scheduled episodes.
2. Show a seven-day strip and selected-day episode list for this week, the previous week and the next two weeks, with a Today action. Use the device's local calendar and time zone for real offset-qualified airtimes, including midnight, daylight-saving changes and week boundaries. An explicit provider date without a reliable time is labelled Time unconfirmed and stays on that calendar date. Episodes without dates stay outside the grid. Keep current or stale successful rows visible when a refresh fails and allow retry. Use TVmaze attribution, a visible keyboard focus indicator, keyboard day navigation, bounded narrow-window layout and reduced-motion support.
3. Airing, sources and captions have separate evidence and plain labels. Opening the calendar or a calendar episode's exact Story Map row loads only schedule/catalog metadata. Find watch options remains explicit. An explicit Check My Library can confirm an exact single-episode file through the existing episode matcher, using bounded same-show local candidates. Only then use per-file caption preferences and verify that the local track still exists. Report English when the track was selected from English search, and show unknown language for imported and older tracks. Calendar state invalidates after file removal or a caption change. No calendar action automatically adds or starts a download.
4. Cover offset and date-only cases, provider failure and request coalescence, persisted follow state, and source/caption evidence boundaries with focused tests. Exercise the Windows desktop calendar and the existing Story Map against a synthetic two-episode season pack. Verify exact resume, next from the existing pack, caught up with a future episode still scheduled, and removal behavior. Complete the full sequential regression, exact independent review, rollback preparation, local installation and desktop shortcut/qBittorrent check.

## Design

- Reuse the existing TVmaze provider semaphore and cache. The authenticated POST /api/episodes/schedule takes an exact showId and returns showId, episodes, undatedCount and updatedAt. Each row includes id, title, season, number, special and schedule with precision, date and at. Use a fresh full episode catalog when present. A cold schedule load requests only the TVmaze episode list, with a small cache and output between UTC today minus 16 days and plus 35 days. Coalesce same-ID work and keep the clock, precision and backward-compatible catalog fields consistent. Recalculate time-sensitive catalog projections on read and intent resolution so an episode can become aired before the provider cache expires.
- TVmaze can return a placeholder airstamp for episodes without an explicit airtime, especially from global web channels. Require both a valid explicit provider airtime and an offset-qualified timestamp to display a clock. Preserve the provider's date-only value, and keep unannounced dates unassigned. Existing manual source fallback remains available when the schedule cannot establish release timing.
- Keep one dialog and a native dialog focus path. Use an accessible, roving day selector and a single list panel. Transition only between days, avoid layout animation and keep control focus during data refresh. Preserve Cinema's dark rose styling and action hierarchy. Use same-origin poster URLs already present in catalog metadata and a deterministic artwork fallback.
- Store calendar follows locally. No accounts, paid services, scheduled polling or background plugin search. Start schedule reads only on opening the calendar with follows or choosing Retry. Limit the client to two show requests at a time. Day/week navigation reuses the loaded schedule horizon. Retain stale results only with an explicit warning. Keep local checks scoped to the selected episode, and keep source status conservative when evidence is unavailable.

References include the [TVmaze API](https://www.tvmaze.com/api), [TVmaze episode policy](https://www.tvmaze.com/faq/15/episodes#airtime-release-time) and [TVmaze's explanation of placeholder times](https://www.tvmaze.com/threads/6422/data-inconsistency-between-front-end-and-api?page=1).
