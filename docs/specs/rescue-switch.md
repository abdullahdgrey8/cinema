# Rescue Switch

When a release runs short of playable video or fails, Cinema can check a second release while the current player stays in place. The viewer chooses whether to switch.

## Acceptance

1. The player offers a bounded set of local replacement files after exact catalog movie title and year or a server-verified single episode match. Source and destination are different torrent hashes and exact file indexes. Normal search stays available with a clearly labeled explicit background-add action, so a new download can be selected without taking over playback. A check can admit an existing verified session, a validated completed HLS copy, a complete direct-compatible video or a partially downloaded direct-compatible video with verified opening and required index bytes. A cold release that needs conversion explains its state while the original stays attached.
2. One muted local preview proves the target decoded. A continuation option requires the last presented source time, exact same story and distinct subtitle evidence, a unique nearby dialogue match, a supported shared Atlas interval and a decoded replacement frame at that mapped time. If this evidence is absent or unavailable, a verified opening permits an explicit start-from-beginning option. All switching is explicit and preserves pause intent and separate watch history. Revalidate the exact local target at commit.
3. At most one rescue check and one short-lived proposal are admitted. A check can use one extra bounded FFprobe process, one short WebView decoder and zero additional FFmpeg converters. It does not alter qBittorrent priorities or add transfers. A background download happens only when the user chooses the separate search action. Expiry, user cancel, another normal selection, changed files, source playback advance or seek, caption changes and stale replies cannot switch the player. Missing or changed media, unsupported files, no matching captions, stalled preview, qBittorrent interruption and decoder errors get actionable feedback. Existing files are retained.
4. Verify native playback with two real synthetic releases and a shifted dialogue moment, a live incomplete/stalled original and a replacement checked before switching. Measure switch-to-frame delay, mapped frame accuracy, conversion process count and any qBittorrent writes or new media preparation. Cover cancellation, ambiguity, same-hash rejection, terminal source, and partial byte safety with focused tests. Run the sequential suite and independent source review. Install locally, verify desktop shortcut and qBittorrent connection, and retain a 2.10.0 rollback snapshot.

## Design

- Client uses exact movie name/year verification from the existing scene model and a recognized catalog ID when available. Episode candidates must match the currently verified TVmaze episode with singleEpisode evidence from the existing file matcher. Similar torrent names are used only to bound lookups. Exclude samples, extras and ambiguous episode files. Backend independently validates exact source session and candidate file identity, disk containment, and qBittorrent state. Never trust a downloaded percent as decoder proof.
- A dedicated authenticated local rescue route issues one expiring proposal, independent of Warm Return. Use existing raw verified-piece streaming and direct codec checks. A partial candidate needs confirmed opening bytes and container metadata. Read and decode only as needed to test the target. Verify backing file identity before commit, allowing expected progress on an unchanged partial inode. A cached HLS copy keeps its exact run and stays protected from trim during its proposal. A cold unsupported candidate never starts a converter. Normal playback selection invalidates proposals and retains scheduler ownership.
- Keep the current player and controls available while checking. Source state and target proof are guarded across awaits. A completed preflight without a decoded frame is not an offer. Cancel releases browser readers and invalidates the ticket. Preserve video and subtitle privacy with loopback reads of already saved tracks; no hidden external subtitle query. Keep the captured scene bound to an actually presented frame, the same source run, and caption revision. Never copy an original absolute time or infer an exact seek from an average offset.
- The viewer may explicitly search for another release and choose a background-add result. This uses the existing authorized add path and makes no playback request for that result. Checking afterwards is explicit. Normal search and normal watch actions retain existing behavior outside rescue search.
- Use calm, staged feedback and keyboard-accessible controls in the Windows player. Offer an opening start only after native opening-frame proof. Reattach the accepted session through the same renderer without ordinary prepare. Offer a clear recovery action if the replacement then fails. No download removal, paid dependency or remote telemetry.
