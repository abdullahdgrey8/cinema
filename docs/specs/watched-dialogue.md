# Watched Dialogue and Catch Up

Cinema can find a remembered line across retained titles and show a short recap before a viewer resumes. Both features use evidence from continuous playback. Collection is opt-in and stays on this device.

## Acceptance

1. Offer Watched Dialogue beside Titles in Search, with a clear opt-in, empty state, keyboard operation, bounded results and a way to pause collection or clear evidence. Dialogue search uses local captions only. The viewer explicitly opens the exact file and chooses Jump once the file, playback timeline, caption and ready seek range are verified.
2. Record only continuous forward passages presented by the foreground main player. Preserve gaps from seeks, stalls, minimization and preview decoders. Existing resume progress and completion provide no watched evidence. Bind coverage to exact file and timeline identity, and retain exact caption coverage separately when the caption is actually shown.
3. Offer Catch Up from a retained resume card and from the player when eligible evidence exists. Show a recent continuous passage ending at or before the resume point. Use only fully witnessed lines from its selected caption, or show a time-only recap when caption coverage is unavailable. Let the viewer choose to replay or resume. Use no inferred plot summary, footage capture or remote analysis.
4. In controlled synthetic media, play an early passage, seek over a middle section, play another passage, and seek near the end. Verify skipped, future and boundary-straddling cues never enter search, counts or Catch Up. Also cover caption replacement and offset, wrong same-torrent file index, stale timeline, minimized playback, native keyboard interaction, normal title search and existing Resume. Confirm zero plugin or torrent actions when reading quotes and Catch Up metadata.

## Trust and scope

- Extend the existing main-video presented frame callback with generation, visibility and continuity guards. Bound media advance by playback rate and wall time, and intersect each continuous witness with the browser’s played ranges. Break on seek, wait, pause, rate change, visibility loss, detach or end. Never fill a positive gap or round it outward.
- Use exact torrent, file index, expected relative identity and length, and verified single-episode identity when available. Keep direct and prepared timelines distinct. Bind converted evidence to a verified run. Reuse the existing player and verified seek path for explicit opening and navigation.
- Bind caption evidence to the selected ID, offset, showing mode and stable content identity or a checked cue fingerprint. Suppress uncertain evidence. Apply the coverage filter before matching or counting. A multi-line result cannot cross an unwatched gap.
- Use at most 48 exact files and 64 independent intervals per group, a fixed serialized bound, no persisted quote text, and bounded cancellable local caption reads. Clear affects this feature’s evidence. Media files, caption files and resume history stay under their existing controls.
- Keep the result interface poster-led with a short quote, timestamp and clear keyboard focus. Use one concise live status and a single-column layout when narrow. Honor reduced motion.

## Working bounds and proof

- Persist at most 128 KiB of evidence. Keep video coverage and only the currently bound caption’s separate coverage for each exact file/timeline record. Prune oldest evidence when either budget is reached. An unsupported or stale binding cannot reveal captions. Keep active samples in memory and debounce writes off the frame callback.
- For each continuous witness require samples within 1.2 seconds of wall time and a positive advance no greater than elapsed time times the playback rate plus 160 ms. The first point after a boundary opens a new witness. Intersect the whole continuous witness with played ranges to tolerate a late played endpoint, while never joining independent witnesses across positive gaps. Quantize stored boundaries inward.
- Allow two concurrent local caption reads, at most 1 MiB per file and 12 MiB total per query, a bounded cue count, and twelve results per page. Any truncation is explicit. Cancel requests on a new query, result mode change, caption mutation or removal. Do not retain snippets on disk.
- Limit Catch Up to the latest eligible contiguous passage before resume, with a maximum 45-second summary window and at most three complete eligible lines. If a clip endpoint cannot be independently bounded, the recap may offer a separate explicit action to open normal playback from the earlier time, clearly distinct from the metadata recap.
- Exercise synthetic direct and converted file identities, two files of one torrent, local caption replacement and offset, rate, pause and hidden-preview behavior. Test a kept positive gap, both boundary-straddling cues, and an exact-result activation when seekable playback data is absent.

## Exact evidence contract

- A file key combines the torrent infohash, file index, normalized expected relative name and expected total bytes. For completed files, the server seals that key with the resolved backing-file object, length, high-resolution modification stamp and bounded first/last byte fingerprints. The opaque seal excludes the absolute path from responses and storage in the client. Bind any known verified single-episode ID and the server-declared playback timeline. Verify the same seal through the existing safe resolver before a result or recap can become actionable. No full-file scan is required. A replacement or mismatch removes the entry from the eligible set.
- Incomplete files may collect volatile evidence in the exact currently attached player. The server confirms the same backing object, exact file layout, nondecreasing torrent progress, and hashes of two previously verified opening windows totaling at most 128 KiB. Choose fixed windows that are complete at admission and recheck those windows before using a volatile witness. If proof cannot be established, keep the witness unavailable. Never promote a partial witness to durable coverage at completion or reuse it across reattachments. Begin a new sealed witness from later frames when the same active file is fully complete. The ordinary progressive player remains usable while evidence is unavailable.
- Each prepared witness also binds the exact run ID and its verified offset to source time. Support a known mapping only, including the app’s verified zero-based conversion when applicable. A regenerated run, changed offset or uncertain origin invalidates old evidence. Clip and seek times stay in the proven timeline. Each exact local validation is read-only, capped and cancellable, with at most two concurrent validations. It starts no plugin search, download, preparation or conversion.
- Compute the witness SHA-256 identity directly from the ordered cue snapshot of the same loaded HTMLTrackElement that will display captions. The existing load event copies its TextTrack.cues, original unshifted times and plain rendered cue text before applying offset. Hash this immutable copied representation only. There is no second VTT read at witness time, so the digest cannot come from a newer disk file than the displayed track. The active element, file, generation, revision and actual showing mode must still match before accepting a first caption interval. Discard late digests or changes. At query or Jump time only, independently read the bounded local VTT, normalize its complete parsed cues to the same representation, and compare the digest and separate exact offset. Include every parsed cue in the digest and decline malformed or truncated input. Browser parse discrepancies, unchanged IDs with different cue bytes, changed offsets, removed files, or a file above 1 MiB make caption evidence unavailable. Video-only evidence can still supply a time-only recap. Show a line only if both shifted cue endpoints are wholly inside one evidenced caption interval.
- Filter and prove evidence before ranking or combining matches. Do not show neighboring context lines. Show the same no-results message for no match and a phrase found only in unwatched material. Counts and ordered results describe eligible witnessed matches exclusively. Generic read-limit messaging depends on eligible files and bytes, never on unobserved cue contents. Add a regression that alters only unwatched text and verifies that the result body, count, ordering and empty state reveal no new information.
- Store one video interval group and at most one selected-caption interval group per exact file/timeline record, up to 64 intervals each. Use version 1, two integer boundary offsets in 250 ms ticks per interval, and a per-group ordered list. Round starts up and ends down only at serialization, then recheck cue boundaries in milliseconds. When an interval limit is reached evict whole oldest intervals. On the 128 KiB serialized size or 48-file bound, evict complete least-recent records until under budget. A corrupt or oversize store fails closed and leaves ordinary history intact. Query only locally retained candidates with eligible caption coverage, in most recent evidence order, two reads at once and at most 12 MiB combined. Cap scoring to 64,000 eligible cues and 60 visible matches. Paginate by 12.
- Opening a result or recap is deliberate. If the verified time is unavailable, keep the Jump action disabled with an explanation. Never queue a seek automatically. On activation confirm file key and seal, current playback timeline, caption binding for a quote, coverage, and ready range again. A time-only replay action opens normal playback at the earlier verified time explicitly. A metadata recap never autoplays into the rest of the video.
- Collection is off on first use. Pausing discards volatile samples, cancels pending writes and leaves already saved evidence available. Clearing cancels pending writes, empties all evidence and the in-memory index, and retains the collection setting, which the viewer can separately pause. Older releases ignore the separate versioned evidence store. Cover both actions in synthetic tests and verify no changes to ordinary history, captions or downloads.

## Coverage relationship and release fixtures

Caption intervals are a subset of valid presented video witnesses, collected only during those witness intervals when the exact selected caption was actually showing. Video-only intervals remain usable without captions. Expose a line only if its whole shifted range is inside both a surviving continuous video interval and a surviving continuous interval for that exact caption. Missing, evicted, shortened or invalidated video evidence suppresses the corresponding caption evidence even when the caption record survives. Eviction may remove coverage, never add it. Test caption showing without a valid video witness, independent caption and video eviction, and both interval endpoints.

The bounded file seal detects ordinary replacement and sampled changes, and does not prove that every byte of a large file is unmodified. Sealed proof requires the full local stat identity plus sampled fingerprints. Partial evidence stays volatile and additionally requires the exact active attachment. Suppress evidence on any mismatch or uncertain provenance.

Required checks include 128 KiB/48-file and 64-interval evictions, corrupt or oversized data with existing history intact, 1 MiB single-file and 12 MiB combined read caps, a maximum of two concurrent local reads or validations, 64,000 eligible cues and sixty visible matches, and deterministic cancellation. Verify that pause and clear preserve resume history, saved caption files and retained downloads, and that the exact prior release can load the same profile while ignoring the separate versioned record. Compare two independently admitted caption fixtures differing only outside witnessed ranges for identical search display. Separately mutate an admitted VTT in place and verify stale-caption suppression, which may remove earlier results without exposing any new line or count.


Test a VTT replacement between the browser track load and digest completion while leaving its ID unchanged. The captured digest must still describe the old rendered cues, and the changed local file supplies no eligible result. Separately change the active track or offset before the async digest returns and verify that no old cue can contribute caption evidence.

## Decoder and commit consistency

- Define one canonical caption serializer for both actual playback and the bounded query-side read. Parse query bytes using the same browser WebVTT TextTrack parser on an isolated track with no media source and no visible output, and require successful load and valid WebVTT preflight. Each tuple is original start milliseconds, original end milliseconds, and cue plain text from getCueAsHTML().textContent, normalized to NFC with whitespace collapsed and trimmed. Sort by start, end and code-point text, retaining duplicates and independently timed overlapping cues. Include empty cues in the digest and exclude them from search. Identifiers, style, region and visual cue settings have no search meaning. Fail closed if parsing, normalization, timing or digest validation fails. The parity corpus covers markup, entities, BOM, CRLF, overlapping and empty cues, settings and malformed input. Store the opaque digest only in the local opt-in record and remove it on Clear. Log no caption content or digest.
- Confirm the exact file seal and timeline before opening a durable witness and again before committing its ranges. Validate at a bounded, debounced commit cadence off the frame callback. Drop the whole uncommitted witness if the backing object, seal, timeline, attachment epoch or collection state changes before validation completes. A file swapped mid-witness or a partial file that finishes cannot receive previously unsealed ranges. Use a fresh witness for later frames. Validate the partial binding before exposing volatile evidence as well.
- The 160 ms margin is scheduling tolerance only. Seek, seeking, waiting, rate change or other lifecycle changes split the witness even when a browser merges its played ranges and the jump would fit the tolerance. A sample more than 1.2 seconds after the previous one starts a new witness with no intervening credit. Test a sub-160 ms seek with merged and late played ranges, and measure native sample continuity with ordinary main-thread load. Keep 250 ms start-up/end-down quantization and prove both boundary cases with native playback.
- Use an authenticated, read-only proof operation around the existing exact file resolver, available piece states and backing-file stat checks. Keep a per-attachment nonce for volatile proof. An old prepared cache marker containing only run, size and duration cannot establish source provenance. Require the exact newly validated run, captured source stamp and declared timestamp mapping. Keep unproved cached conversions available for normal playback, with no dialogue or Catch Up evidence for that timeline.
