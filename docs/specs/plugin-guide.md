# Plugin Guide

Roadmap 18 expands the Windows Sources view. A viewer can open a plugin and browse categories and current title suggestions without typing. Search evidence explains what the plugin returned for those suggestions.

## Scope

- Show Overview, all advertised native categories, and separate Korean drama suggestions where a plugin advertises TV. Misc groups non-media categories and General uses the advertised `all` search. Preserve the native category IDs and use `tv` for Korean results. A plugin that only exposes `all` shows General topics without a claimed Movies, TV, or Anime category.
- Overview retains its bounded four shelves and eight initial suggestion cards. Every advertised category has a direct accessible selector, including categories outside the first shelves. Opening a dedicated category displays its existing pages. Keep individual release choices and the scoped manual search escape hatch.
- For media, offer This week and This month with the same current chart provider pipeline as Discover. Use actual row date, period, and provenance when available. A chart or topic supplies suggestions. qBittorrent searches the selected plugin for each suggestion on the visible page only. Keep suggestions and results distinct in wording.
- Summarize the current visible sample per shelf. Each card contributes once to seeded matches, completed checks with no seeded match, pending, unavailable, or upcoming. A running job that reaches the limit without a seeded match is a timeout. A returned matching seeded result can remain actionable even if the job reached its limit. A missing capability or failed check belongs in unavailable. Only a validated completed result response can establish an empty check. Counts describe only this page and never rank an entire plugin or imply all its content is listed.
- Poll during active work, guard old responses during category, period, page and refresh changes, and avoid recurring probes once settled. A single bounded follow-up for late artwork is allowed. Keep accessible focus across status updates, restore the plugin card on Back, and provide manual retry or a different category on error. No new background download actions, plugin configuration actions, scraping of plugin internals, new credentials, catalog endpoints, or claims of a provider-native catalog.

## Public seams and verification

1. Existing browse endpoints continue to accept `name`, `category`, `page`. An optional `period=week|month` and `collection=korean|general` select the corresponding provider window or collection. The backend validates the collection against the real plugin category, distinguishes `overview` in its UI projection, and scopes qBittorrent requests to that exact enabled plugin and native category. Fixtures exercise categories and Korean chart routing, page coverage, plugin disabled or category changed while a lookup was pending, bounded requests and absence of transfers.
2. Confirm seeded result dedupe, a stopped empty or unseeded search, a timeout with and without useful partial results, failure, queued and upcoming states, and safe cancellation. Filter malformed results before ranking. Make the visible-page numerator and denominator unambiguous.
3. Use keyboard-first Edge and an isolated native Windows WebView2 fixture for overview, week/month, Korean, Misc, navigation/pagination, focus, 360 px and reduced motion, ready and error states. Run the app regression suite and independent source review. Verify the installed shortcut and library/qBittorrent continuity.

The qBittorrent Web API exposes advertised search categories, a named plugin, a search pattern, and search results. This design uses that public search interface. [qBittorrent Web API](https://github.com/qbittorrent/qBittorrent/wiki/WebUI-API-%28qBittorrent-5.0%29)

## Implementation boundaries

P1. Serialize enabled/category lookup and browser allocation in request order. Retain at most one active discovery instance per plugin, tagged by exact native category and collection, and close it before replacing a different scope. Pass period into the existing discovery request and catalog adapter. Echo plugin, category, collection, period and requested page; the client checks exact echo, abort and generation. Topic-only views ignore period.

P2. Before a new plugin job starts, obtain the current enabled plugin and exact advertised native category; no fallback to all. Validate result status as Running or Stopped and result rows as an array. Only Stopped may establish no-match. A useful partial result at deadline remains actionable with timed-out provenance; no timeout, bad response or transient error is cached. Retain per-plugin scoped source cache and existing dedupe. A transport Retry repeats the same request. Explicit Recheck this page refreshes only the visible sample and invalidates only its keys. It neither clears other pages nor refetches global chart providers.

P3. Bind card availability to the current generation; suppress stale results before the next response is ready. Completed cached values are tagged with original checkedAt. Count each visible card once in matched, noMatch, pending, unavailable or upcoming, reporting the real visible denominator and dating the observed checks. This is a per-page sample, with no guarantee that a title explicitly searched in two separate collections needs only one job.

P4. Client only polls while the current view is loading or checking, stops on settlement and when closed, and allows no automatic rerun. Disable passive expiry or metadata revision-triggered reruns for plugin-only discovery. Re-read plugin status on explicit interaction and each new job. Browsing state checks remain bounded and the active exact source can be rechecked on demand.

P5. Overview uses selector ID all. Each advertised native category has stable native:<category>, Misc is an optgroup containing the non-media native categories, General has ID general mapping to category all and collection general, and Korean dramas has ID korean mapping to category tv and collection korean. Do not show General or Korean without their advertised categories. Overview keeps Movies, TV, Anime and available Misc as before. Use strict known row IDs, and dedicated Korean renders only Korean chart rows. No client nativeCategory filter.

P6. Keep one stable polite live status and use existing updateHTML focus retention on stable keys. On category change retain category control focus, on page transition keep the page control or a programmatically focused shelf heading, and on Back restore the originating plugin card. Place the pager above cards and expose a focusable Retry after a transport failure. Verify using keyboard in both runtimes.

P7. Keep actual row.source, row.periodLabel, row.periodStart, row.periodEnd, row.publishedAt and row.stale as available. Chart periods and actual published dates remain separate from the local search check date. Do not relabel provider fallback. Check a fixture where a saved dated chart is served or the requested provider period is unavailable.

F-EMPTY-CHART. A dedicated media view remains selectable when its chart cannot supply any suggestions. The page has a visible chart state with an explicit provider-unavailable or no verified titles message, according to the actual row. It starts zero plugin search jobs. Keep week/month available and offer Open scoped search without submitting a query. Transport failure gets a separate Retry action. Tests use an empty Korean chart, unavailable Movies chart, and provider fallback metadata.

F-TIMEOUT-BUCKET. An exhausted search with no usable seeded result is unavailable with timeout provenance. It is never counted as pending or noMatch. An exhausted search with a useful result counts as matched with timeout provenance. The five buckets must sum to the actual visible suggestion count on every page.

S-CACHE-OWNER. Keep the existing bounded completed-results cache across explicit collection/category switches within one active plugin. Per-plugin map max 200, expiry 30 minutes only during an explicit query, clear on disabled or capability change, and let the LRU discard it with the plugin. Key by normalized title, kind, year, native category and plugin. Invalidate only visible keys for Recheck this page. Exact row IDs remain required.

PR-CACHE-LIFETIME. Each plugin-browse LRU entry is keyed by exact plugin name and owns one Map. Pass this Map as the optional sourceCache constructor argument to every scoped createDiscovery instance for that entry. The default Discover instance still owns its own Map. Await closing the old scoped instance before replacing it. Cap the injected cache at 200 entries using the existing eviction pattern. Disabled, changed capability or evicted plugin entries discard that Map. Test Movies then another category then Movies, confirming no new searches for completed cached titles. Test recheck of page 2 followed by page 1 and confirm only page 2 was invalidated.

PR-CACHE-KEY-EXPIRY. Plugin cache keys use JSON tuple [normalized title, kind, numeric release year or empty, exact native category, exact plugin name]. No row ID or period enters that key. A stable title from TV and Korean that resolves to the exact same key deliberately shares evidence. Different title, kind, known year, category or plugin cannot share. Chart selection still requires exact row IDs from the provider independently of cache keys. This replaces the earlier P3 cross-collection caveat. Age over 30 minutes is evaluated only when starting lookup from initial view, changed page, period or category, or an explicit Recheck. Same-scope passive polling does not schedule another run, and displayed evidence retains its actual checkedAt even when it ages.

S-CHART-STATE-SHAPE. In a dedicated media view the server retains one selected row even when it has no items. Row chartState is available, stale, empty, or unavailable. Missing row or provider-unavailable row with no items is unavailable; provider row with no verified items is empty. A stale dated row with items is stale and still exposes actual period and source. The client renders the supplied row state, without deducing it from missing HTML or changing the selector.

PG-F1. Explicit Recheck flags the newly selected request generation as bypass-cache. Do not clear the injected map in discovery access. Each worker first resolves a missing film year through existing enrichment, then computes the final lookup key, deletes exactly that key, and skips reading it for the recheck. A verified result may then repopulate only that key. Never precompute cache keys from unenriched card summaries. Test yearless Movies with enrichment, scope return, and page-2 Recheck leaving page-1 cache intact. Legacy Discover can keep its original cache refresh behavior.

PG-F2. The desktop initial open, changed selection, and explicit Recheck use the existing active routes. Follow-up GETs set poll=1, which obtains only the exact in-memory snapshot for the echoed plugin/category/collection/normalized period/requested page. It makes zero qBittorrent calls and starts no run. A missing or superseded passive scope returns a retryable conflict. Legacy GETs without poll retain revalidation. Before each new qB search/start, lookup does a fresh search/plugins validation against the exact enabled plugin and native category. If definitely removed, disabled, or capability signature changed, mark the plugin run invalid, clear its injected cache, abort further starts, and suppress late results from existing workers. Any jobs already started still go through stop/delete cleanup. A transient API error is reported separately. Test disablement between two starts and verify zero qB calls attributable to passive polls.

PG-BOUNDED-RESULT. A no-match only means the checked returned results contained no usable seeded match. Keep the existing limit of 300 rows per qBittorrent result read, rank and deduplicate within that sample, and use that wording for empty results.

PF-1. Mid-run confirmed invalidation flips a run-local valid flag before clearing the injected cache. Guard both cache writes and UI publication with generation and validity. No further starts. Existing jobs complete cleanup through stop/delete; all current affected cards except upcoming settle as unavailable with a plugin-changed reason, with pending zero and counts summing to visible count. Test the loss between two starts and check late cache and cleanup. The existing discovery get/access stays active; add a separate peek method to get its snapshot without starting a run.
PF-2. A passive transport error stops the timer and shows a focusable Retry connection which repeats the same passive poll. A 409 superseded scope stops the timer and instead offers Reload this page, which issues one active GET only after activation. Initial active request transport Retry repeats that same active intent. No automatic active retry from a stale scope. Explicit source Recheck only reruns the selected visible page and catalog adaptation does not forward refresh to metadata.discovery.
PF-3. Stop polling on settlement. Before explicit Add or Watch from a release card, use its server-registered seenAt. At 60 minutes or a missing source registration, preserve the current view, show an expired choice message, and focus Recheck this page without adding or searching. Existing library Open uses its local hash. Test the expired state with a controlled clock past 60 minutes and zero transfers. Guide release keys include the exact plugin and native category in the hash input so an ordinary search or another plugin returning the same torrent cannot overwrite the selected guide registration. This leaves ordinary search keys unchanged.
