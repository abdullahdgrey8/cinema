# Plan a watch

The Home screen should turn available time and the library already on this PC into a short list or an evening program. This is the shared implementation slice for roadmap ideas 15, 16, and 20.

## Acceptance

1. **Tonight in Three Picks.** Offer up to three distinct titles with a time budget, optional mood, and concise evidence for each choice. Draw from loaded charts, saved titles, and the current library. Separate **Ready in player**, **On this PC**, **Find watch options**, and **Not checked**. A title with an unknown runtime cannot qualify for a hard time limit. A series average cannot qualify as a particular episode's runtime. Distinguish remakes, and never connect a local file to a title solely through a similar name.
2. **Movie Night.** Suggest or assemble a two-title program. Let the viewer reorder it with buttons, adjust one intermission, and see the known total or the fact that part of the total is unknown. Save it on this device or export a bounded, versioned JSON program with title metadata. Keep paths, hashes, source URLs, votes, and video out of the export. Removing a local file keeps the saved plan and updates its readiness.
3. **Pick Together.** Two people vote privately on one stable shortlist. Show a neutral handoff between them and reveal only the intersection. Use confirmed readiness to order shared picks. The vote is memory-only and closing the planner clears it. A tied or empty result offers another shortlist without exposing individual ballots.
4. **Windows experience.** All three modes share one Home entry, modal and candidate model. Opening the planner and editing a plan never searches for a torrent or adds a download. Opening a title delegates to the existing title or player action. Any read-only verification of local files is explicit, limited and cancelable in the UI. Support keyboard focus, stable cards while voting, and reduced motion.

## Shared model and verification

- The three modes share title identity, runtime evidence, availability, and display reasons. Distinguish a measured file duration, a catalog film runtime, and a known episode duration. Count runtime once per planned item and add a break only between items.
- Use provider title identity or a release's existing exact library association for playback links. A normalized title, year and kind can collapse duplicate chart cards without granting a file association. A completed torrent becomes **On this PC** only after Cinema verifies a playable file for the selected item. A confirmed active playback session can earn **Ready in player** for that specific file.
- Preserve existing discovery schedules, current playback, and retained downloads. Keep planning local and use loaded or cached inputs first. Keep the older home and search paths available.
- The discovery callback already delivers the rows used by Home. Capture those rows and their period/source labels without calling the discovery endpoint again. Preserve stale-chart dates in any ranking explanation. Merge saved entries by trusted provider identity where present. Leave standalone library entries separate when the link is uncertain.
- Match a chart release to a local item only when it carries that release's exact existing infohash or has an independently verified binding. A read-only file verification action checks a bounded number of local candidates and uses file-level completion and playability. Exclude samples and ambiguous packs. Episode readiness requires a verified episode-to-file match. End or ignore the check if the planner closes, the library disconnects, or the current snapshot changes.
- Open playback by the verified hash and file index through the current player. The planner itself never calls prepare. When verification cannot distinguish a completed playable file, leave readiness unconfirmed. Preserve saved plans across file removal while removing stale readiness.
- Test a 35-minute budget against unknown and 40-minute items, a double feature with a 48 + 32 + 10 minute total, a removed local file, remakes, sample-only and ambiguous torrents, an interrupted verification, a ballot with exactly one overlap, an empty match, and reset on close. Verify the actual Home entry, keyboard journeys, and metadata export in Windows separately from the shared selection rules. Record that opening or editing a plan issues no discovery, source search, add, or prepare requests.

## Integration decisions

- One stable Home strip opens a native dialog with three keyboard-accessible modes. Use a restrained Cinema rose accent, poster-led cards, a calm handoff view and reduced motion. Preserve focus after rerenders and restore it to the launcher when closing without navigation.
- A bounded verification action inspects at most six connected library items sequentially through a read-only endpoint. Reuse the media resolver and check the actual file size, without a layout export, media probe, playback session or qBittorrent mutation. Only one eligible non-sample video can qualify as a standalone completed item. For a series, exact current verified playback can offer the selected episode. Unverified or compound season packs do not qualify for a hard time budget.
- Measured video time uses the exact saved file index and basename or exact active player state. Keep estimated film runtime visibly labeled and round measured durations up for the budget. No average series runtime goes into the picker.
- A stale or disconnected library loses readiness claims. The private ballot uses an immutable list of up to six candidate identities; refresh the deck only when a viewer explicitly requests a new round. A metadata-only saved program is safe to reload even when its title or file disappears.
- Ship from the isolated candidate after focused and sequential regression checks and native WebView2 QA. Reconcile source against the 2.6 baseline before updating the production folder and check the real desktop launch route. Preserve the installed app until the candidate passes the release checks.

## Runtime, private voting and release checks

- Loaded Home rows are a partial chart snapshot, with at most a bounded recent set retained in memory. Keep their date and provider labels. Unsearched titles ordinarily have no local association. Read runtime from a film row or an additive My List runtime snapshot. Older saves stay eligible with unknown time. Exact already-observed durations come from Cinema history by hash, file index and basename, or from the exact active player. Neither approach runs a media probe. Normalize movie, TV, Korean drama and anime as separate display kinds. Use known catalog namespace and ID to merge evidence. The optional mood filter maps visible genre labels through a fixed table and gives no weight to absent genres.
- Opening the planner, switching modes, editing, voting, verifying and exporting do not initiate catalog or source work. Opening a title is a separate explicit navigation. Close the planner before delegation to the existing details or player, where the existing discovery behavior may apply. Use the existing openPlayer(hash, intent, indexHint) seam for a verified file; its file lookup refuses a wrong explicit index. Treat ordinary Home polling as background traffic in QA, with a fixture that counts planner-phase requests separately.
- Pick Together uses approval voting. Selected IDs live only in controller memory. Remove the first ballot from the rendered DOM and live text at handoff, with a neutral heading focused. Person two sees the same stable candidates without any marked answers from person one. On reveal, delete both individual ballots and order only shared picks by current verified readiness, then stable order. Both modes of close and leaving the voting mode discard the round. A new shortlist rotates independently of individual answers and never exposes vote counts or skipped titles. Neither browser storage, export, nor logs include ballots.
- Save a versioned, bounded local program on a new storage key. The local record can use a private candidate key to resolve the current card, while retaining sanitized display metadata when it disappears. Export projects only ordered plain titles, years, media kind, runtime minutes and its evidence class, plus schema version and one break length. Reject or omit path-, URL- or infohash-like title values. Limit the program to two titles and 8 KiB, use a fixed filename, and offer no file import. Try a user-initiated same-origin Blob download in WebView2. If native QA shows it is blocked, use a bounded allowlisted loopback attachment and retest it.
- File verification is a fact about a supported media extension, exact qBittorrent file completion and a real file with the expected size inside the configured download roots. It is not a codec guarantee. Use a read-only qBittorrent snapshot and the existing containment-aware resolver, bypassing the piece-layout path. Return only an index, basename and size or an unavailable result. Cancel stops queued checks, aborts the current HTTP observation and discards results after a changed connected-library fingerprint, close or timeout. A filesystem lookup already handed to the OS may still finish read-only. Re-evaluate proofs against the latest library and clear them at disconnect, on a changed item, after a short expiry or close. Ready in player requires the current exact file with browser playback-ready data and no failure, pending resume or recovery.
- Native QA uses a separate WebView2 profile, port and temporary Cinema data directory with fixture downloads and no production credentials. Verify Home launch, keyboard mode switching, close/return focus, readiness, a private handoff and shared result, and actual saved metadata export. Before cutover, snapshot only the exact 2.6 source paths that will be replaced; preserve the existing data/profile and verify production is idle. Check version and new assets after restart. On failed health, restore the previous source from that snapshot and bring 2.6 back. Browser-storage changes use a new versioned planner key and additive My List fields.
