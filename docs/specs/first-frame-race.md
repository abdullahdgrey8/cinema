# Fast Start

Fast Start lets the viewer ask Cinema to check one exact alternate copy while the originally selected video is still starting. It can use a faster verified copy that is already in My Library. The two downloads remain under the viewer's control.

## Acceptance

1. During a slow start from the beginning, offer Fast Start only for a recognized movie title and year or a server-verified single episode. The viewer chooses one exact alternate from the existing library. The normal download and Rescue paths stay available. The action explains that Cinema can switch automatically before the original plays. Checking causes no add, pause, priority change or delete in qBittorrent.
2. The original continues to prepare and wins as soon as the current visible video presents a decoded frame. The alternate can win only after WebView decodes a frame near the beginning and another at least three seconds into its verified opening, then confirms the exact file again before attaching. Skip the check when resuming a saved point or when playback is paused, hidden, minimized, retargeted, failed or stopped. Show clear waiting, cancellation, unavailable and timeout messages. A lost, late or failed offer must leave the original eligible to play. If a committed alternate later fails, the original is available through the existing reopen action.
3. Use at most one 16-second comparison, one extra bounded FFprobe of at most five seconds, one short muted WebView decoder and one prefix read of at most six MiB. A bounded read-only wait for opening bytes may precede the probe. Reuse the verified-piece stream and pin the exact primary session across its readiness transition. Keep one encoder and use no second normal prepare. Scope the alternate to direct-compatible MP4/M4V with its opening index in the verified prefix. Cold candidates that need conversion or bytes outside that window stay available through ordinary playback.
4. In a paired controlled startup experiment, use two distinct real synthetic video releases and replay the same timed partial-piece feed. Include an alternate win and a primary win, repeated if practical. Compare common-decision-to-visible-frame time, post-start stalls over a defined window, observed qBittorrent bytes and preview bytes. Gate release on a meaningful alternate win, no material primary-win regression, bounded extra work and real native playback. Cover stale results, cancel, unsupported files, no verified runway and request races. Run the full sequential regression, exact independent source review, and verify the locally installed desktop app. Keep the feature experimental if the performance evidence misses its gate.

In the controlled alternate-win case, require at least one second and a 20 percent improvement in the paired decision-to-frame time. In the primary-win case, require no more than 500 ms extra. Compare stalls for the first eight seconds after playback starts, with at most 500 ms added stalled time. The comparison itself adds no torrent traffic by instruction and should cause no extra peer bytes in the controlled feed. Record the measured local preview bytes and the fixture's limits.

## Design

- Extend the existing authenticated Rescue admission route with an explicit fast-start purpose. Apply the same movie or episode identity and exact file checks. A missing prefix can return a bounded waiting status before any inspector starts. Keep a single shared rescue/preflight slot. A proposal can follow the original session's transition from no URL to its ready URL, while generation, file, session and ordinary-selection guards remain in force. Commit revalidates backing files and adds the alternate ready session without advancing the ordinary scheduler or retiring the primary. The browser is responsible for retaining the primary if it presents before the exact commit response is accepted.
- Inspect only direct-compatible MP4/M4V alternates. Compute available contiguous verified bytes capped at six MiB, and confirm the opening MP4 index fits in that prefix. Fetch that exact range through the regular guarded stream. Validate the same-origin attachment URL, the range response and byte length before constructing a transient local Blob. A muted short-lived video proves both frames with native frame callbacks. Use the regular video element and original file URL for visible playback. Treat the extra preview as a local read and measure it independently of torrent network traffic.
- Reuse the existing Rescue candidate list and exact attachment handoff. The startup action has distinct language and a cancel control. It offers a single alternative while the original remains in the foreground. Track the original by generation and session until a real visible frame or a stop signal wins. Clear timers, preview, request and ticket on all outcomes. Preserve accessible focus and reduced motion.
- The existing qBittorrent API exposes piece status and file priorities. Per-piece deadline scheduling belongs to the torrent engine and is outside this comparison. Use neither a second torrent engine nor speculative alternate downloads.
