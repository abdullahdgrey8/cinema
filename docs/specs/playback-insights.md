# Playback runway and Release Passport

Cinema should explain what can play now and how the selected release actually behaves on this PC. This delivery round covers roadmap 10 and an active-player Release Passport for roadmap 13. It also supplies measurement boundaries for later continuity and source-learning work.

## Acceptance

1. Show the amount of video continuously buffered from the playhead. For growing HLS, distinguish it from the contiguous span already published in the active fragment playlist. A seekable range, an aggregate prepared duration, a later island or a torrent percentage does not prove that the player has buffered a span. Incomplete direct playback shows browser buffer only. A completed title can show its verified full-file or completed-HLS state without asserting a stall guarantee.
2. Give a cautious, short-horizon runway estimate only on growing HLS when sustained observations agree that playback is catching up to the prepared edge. Account for playback speed and segment publication in batches. Show uncertain pace when the evidence is mixed and withhold a countdown after a seek, pause, rate change, recovery, incomplete evidence, backgrounding, or new media generation. Check the prediction against real playback in a controlled incomplete-stream fixture that stalls and later recovers. Do not generalize that fixture to arbitrary peers.
3. Put the Release Passport in player options for the exact chosen file. Separate filename labels, local probe facts, and observed browser playback. Reuse existing probe data and show missing facts honestly. Use a presented frame for first-picture timing, exclude user-delayed starts, and count sustained waiting after a frame while playback is intended. Do not count startup, voluntary pause, seeking, final end, or stale events as interruptions. Clear facts on selection/removal. For automatic reattachment to the same file, keep prior observed attempt metrics and reset the forecast. Raw paths, probe payloads and outbound telemetry are out of scope.
4. Provide a compact, accessible Windows player presentation, with state-change-only announcements, keyboard-accessible details, and reduced motion. Preserve play, resume, seeking, captions, and download/priority behavior. Run targeted regression and full sequential checks, independently review the current source, verify the incomplete player in an isolated WebView2 profile, and release locally after the production window is idle.

## Implementation

- The runway controller consumes a monotonic clock, the exact active playback generation and URL, native browser buffered intervals, confirmed fragment intervals, playhead, playback rate and phase. It stops at the first positive gap. Forecasts never use peer count, bandwidth, completed percent, full browser seekable extent, or FFmpeg generated time.
- Observe a bounded rolling window with multiple separated intervals over at least twelve seconds. Reject stale, discontinuous or hidden samples. Compare the recent prepared edge's growth against playback consumption. Require a conservative upper growth bound below consumption before showing a conditional low-buffer estimate. Use coarse displayed buckets instead of a countdown that ticks each second. A steady or growing prepared edge does not promise uninterrupted playback.
- Project a small allowlist from the already successful local probe, including normalized codec names and valid dimensions. The browser contributes displayed dimensions and observed first frame via its presented-frame callback when available. A known format without a presented frame remains a probed fact. Attach and frame callbacks bind to the current source generation. Track an interruption only after actual video presentation with ongoing play intent, low ready state and a meaningful waiting interval, and end the interval on playing, user pause, seek, error, or explicit removal. Keep all observations in memory for the selected file.
- Use a narrow line by the existing Playback Map and place the richer details under Options. Update visible buffer counts coarsely. Announce only meaningful waiting or risk transitions so the player does not interrupt dialogue or keyboard navigation. Both locations use Cinema's native-window theme and reduced-motion settings.
- Build two independently verifiable seams: browser buffer and forecast first, then an exact-file evidence view reusing the same lifecycle. Automated tests exercise gaps, false seekable coverage, a moving or stalled edge, rate and seek resets, and spurious waiting. In the synthetic incomplete HLS fixture hold later pieces until playback stops, then supply them and confirm recovery. Capture observed position, forecast bucket and actual wait. Recheck the real desktop shortcut, version and assets after a scoped local cutover. Snapshot exact previous production source files and restore them if health fails.
- Warm Return, temporary fallback playback and historical source ranking stay separate. They require explicit background-session and converter-budget behavior that this telemetry does not modify.
