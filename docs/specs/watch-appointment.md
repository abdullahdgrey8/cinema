# Ready by

Make a watch appointment from the existing library. Pick one title, a local date and time within the next 12 hours, and an optional separate backup. A persistent in-window card keeps the appointment visible while browsing. The viewer can stop it, check again, or explicitly play a verified file. Opening the planner and editing the fields cause no appointment checks.

1. **A clear decision by the deadline.** Add a Ready by mode to Plan a Watch. Show the exact primary and backup, a real selected-file progress indicator, the deadline, one honest status per choice, and a quiet in-app announcement for material changes. The panel and a stable cross-view card open each other without shifting focus during checks. Distinguish finding the file, downloading, paused, on disk, direct play checked, disconnected, and unavailable. Show whether the primary was still waiting at the chosen time or had a recent verified result. Stop periodic checks at the deadline or when the window goes away. The appointment lives in that open Cinema window. No automatic playback, new download, resume, or operating-system notification.
2. **Evidence, not promises.** Resolve each exact live infohash to a single non-sample video and bind its file index, relative name, and size into an opaque file key. No title matching, ambiguous packs, or local paths returned. The clock and forecast concern only download completion. Estimate a cautious window from at least four positive exact-file samples over at least 30 seconds, rounded outwards to minutes. Refuse unstable, stale, stopped, reversed, or disconnected evidence. Never present a peer-dependent estimate as readiness. When a completed file is present, use a short idle-only read-only codec probe for supported direct-play containers, or revalidate the exact current direct session. Mark other completed files as needing ordinary player preparation. The backup uses the same proof standard.
3. **Keep current playback independent.** Make at most one check per window at a time and one service-side codec probe globally. Poll every 12 seconds only for an explicitly started visible appointment, with an immediate fresh check on a user Play or Check now action. Cancel checks on stop, hidden window, connection change or deadline. A probe is detached from media sessions and never starts conversion, changes priorities, writes to qBittorrent or adds downloads. Cancel its process on foreground prepare, media reading, removal, shutdown or aborted request. Validate contained real file identity and current qBittorrent selection before and after probing. Limit probe time to 2.5 seconds, output to the existing bounded parser, input protocols to local files, and formats to supported direct containers. A small in-memory codec cache may reuse only an unchanged exact disk stamp. Fence results with a service-and-connection epoch and a client generation. Before an explicit handoff, obtain a fresh result and pass the exact file key into ordinary preparation. Changed or missing media returns to an actionable status instead of playing another file.
4. **Verify the actual decision and handoff.** Test dates, pauses, ETA uncertainty and deadline outcomes, ambiguous and removed torrents, stale connection or file keys, direct-format proof and busy foreground gating. Isolated Windows QA covers keyboard creation, browsing with the card, a deadline arriving while the primary stays incomplete, a verified backup that plays a real frame only on explicit action, focus and reduced motion, and no additional mutating qB commands during observation. Run sequential regression, review the exact source, and verify the installed shortcut and library. The proof covers completed direct-compatible files. Legacy restored HLS copies are outside this release because their marker does not identify the full backing source.

## Decision and ownership rules

Sample each exact file with the service's monotonic observation clock. Use four consecutive samples spanning at least 30 seconds and 8–20 seconds apart. Each interval needs at least 256 KiB or 0.001% of the file, whichever is larger. Drop the window on an identity change, reversed or stalled progress, pause, stale response, hidden window, or a fastest-to-slowest interval ratio above 2.5. The earlier estimate uses 115% of the fastest observed rate and the later estimate uses 65% of the slowest rate. Round outwards to minutes, and withhold ranges wider than three hours or ending beyond twelve hours. The UI labels this an estimated download window. It is independent of the wall-clock deadline and of playback readiness.

Resolve the time field to an absolute local instant and display its timezone. Refuse DST gaps and ambiguous repeated wall times. Use wall-clock comparisons on the timer, focus, and visibility events. Before the due time a visible window can check again immediately. If the due time arrives while hidden, disconnected, or with no applicable check in the preceding 20 seconds, show that Cinema could not confirm readiness at that time. A result completed after the due time can help with a manual Play but cannot rewrite the historical outcome.

The single detached verification slot retains its abort and child completion until the process exits. Foreground preparation, external reading, a rescue or warm switch, removal, shutdown, and canceled HTTP observation revoke it. Wait for the matching probe to release the file before a removal can proceed. Confirm idle state before and after, including existing children, viewers, streams, conversion, rescues, warm leases and dialogue work. The supported media formats are forced through the specific local-file-only demuxer. Stat the contained file before and after, and bind device, inode, size, modified, changed and birth times into the opaque Play proof. Reuse cached codec evidence only when the same full stamp and exact selected file still match.

Play is shown for a freshly checked completed direct file. An unavailable or unverified selection has a status and a Check now action, with ordinary browsing and the library remaining available. Pass the epoch, exact key, and complete disk proof through the ordinary player, including retries. The server revalidates the current completed file from the same prepare input and rejects a stale proof before any new session or torrent-priority action. A changed file returns an actionable error. Do not downgrade the appointment action to a regular unchecked start.

The cross-view card stays in the main browsing surface and remains inert behind any open modal player. The planner tracks which button opened it and returns focus to that button on close. Keep the dialog and card nodes stable. Only the visible surface announces material state changes, and checking or estimating never shifts focus. Keyboard and reduced-motion checks cover both surfaces.
