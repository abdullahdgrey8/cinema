# Warm Return and watching while a title prepares

Cinema can keep preparing one title while the viewer chooses another title that already plays locally. The user can then return explicitly to the original preparation or its same verified run and viewing position. This round implements the one-converter path for backlog ideas 11 and 12.

## Acceptance

1. The player offers a deliberate switch only after an exact source file has a current preparation session. The short fallback list contains only ready, complete files from earlier verified sessions on this service. A direct file needs current disk size and previously inspected compatible codecs. A completed HLS copy needs its validated completed manifest and referenced segments. A different file in the same torrent, an incomplete or replaced file, missing media or stale cache cannot be chosen. Revalidate immediately before changing the player. An empty list explains how a title becomes eligible.
2. Switching retains the original selected file, still-running preparation and exact existing published URL when one is available. A single, temporary Return action appears in the fallback player and its dock, with honest readiness and no automatic navigation. Returning restores the exact file and a saved position only when it came from that same playable run. If the original is still preparing, Return opens that existing preparation. The choice preserves fallback history.
3. One short-lived service lease and one encoder are permitted. Fallback play and Return reuse verified ready or preparing session state without calling prepare, adding a torrent, probing a fallback or changing qBittorrent priorities. Exact hash, file index, original session ID and optional published run bind the lease. Expiry, dismiss, normal playback selection, source removal or invalidation retire the offer. A detached converter can be retired on expiry while a currently observed stream keeps working. An encoder slot stays owned until process close and asynchronous finalization. A fallback decoder error or stale status leaves an explicit return or error and never silently starts another conversion.
4. Provide a native keyboard-accessible chooser and a compact player and dock return control with state-change announcements and reduced motion. Verify two actual decoded titles and a native A-to-B-to-A transition, A range growth during B, exact URL and restored position, process count and original transfer behavior. Cover rejected same-hash and stale-file cases, lease expiry, cached HLS eligibility, and canceled/late operations. Run the full sequential suite and independent source review before local release. Keep the 2.8 source snapshot for rollback.

## Implementation boundaries

- Use a read-only bounded list from existing verified sessions. Source eligibility is exact selected identity and current service session, never a library title match, presumed MP4 compatibility or qBittorrent percentage alone. Exclude the source hash. A user sees why the list may be empty. Switching revalidates the exact disk file and ready session before replacing the visible player.
- The authenticated switch, return and dismiss operations own the single lease. The status read is observational and does not extend it or count as a viewing heartbeat. An ordinary live player heartbeat protects against retiring a stream after a lost switch response or another active viewer. An already-published A run is pinned and rechecked. A preparation without published media can adopt its first real run. A newer ordinary selection can take precedence. No qBittorrent mutation is added to warm operations.
- Attach existing state through the ordinary media renderer without ordinary prepare or first-file guessing. Capture browser playback position and episode identity in the client, bound to the current generation, exact file and run. Preserve pause intent on returning, and restore no unverified seek. Keep stale response guards and clear the offer on explicit Stop or a different normal selection. Leave downloads and user media in place.
- Keep the current single-encoder scheduler. Hold its slot during preemption, retry, cancellation, sparse-keyframe restart and warm retirement until actual close/finalization. Refuse same-hash warm handoffs. Measure converter process count and memory/CPU during the controlled switch. A general simultaneous conversion tier would need separate measured admission and lies beyond this delivery.
- Existing release metadata, captions, resume history and file-download paths stay authoritative. Use isolated source and WebView2 fixtures, not the production downloads, for media and fault tests. No paid services or external telemetry.

## Lease and transition details

- A lease lives for 75 seconds from the accepted switch. The active playback observation grace is 6.5 seconds. Status polling of the parked title cannot extend either. If the switch response is lost and the original viewer keeps polling its normal playback session, the expiry operation clears only the lease. Retire a detached incomplete converter after expiry without altering qBittorrent priorities. Published media remains protected while a reader or writer owns it.
- A validated service session ID binds the exact original and fallback state across awaits. When an original has already published a URL, retain it and require a match on return. A not-yet-published preparation can acquire its first URL. A retry, removal, stale response or replaced run cannot restore a position against the wrong timeline. A source that is still preparing can be opened explicitly in that same state.
- If a prior encoder is closing or finalizing, wait in the existing preparation queue until the slot is released. Fallback and return remain explicit. A rejected switch leaves the current player intact. An invalidated fallback opens no new conversion and leaves the original return action available while its lease is valid.
