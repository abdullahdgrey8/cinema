# Preview an available scene

An incomplete video can contain a verified scene beyond the player's contiguous seek range. Cinema gives the viewer a short preview of that scene without moving their current picture or changing how qBittorrent downloads the file.

## Acceptance

1. From Scenes, an explicit preview action for a time outside the current seekable range can play a matching short clip if the opening index and scene packets of the exact attached incomplete file can be independently verified. Support bounded fast-start H.264 and AAC-LC MP4 or M4V with the compatible timing profiles proved in the lab. Copy from the preceding verified IDR. The card seeks to the exact translated clip time before it enables Play, and the first presented frame must match the source within one presentation frame. Missing, unsupported or unproved data gives a truthful status and no clip. The file remains incomplete in the positive test and a gap separates the opening from the late scene.
2. The preview has its own short lifetime, decoder, controls and read-only lease. It starts muted and requires an explicit Play action. The ordinary picture, position, pause state, selected captions, download priorities and watch history stay on the current attachment. Keyboard focus, reduced motion, retry, Escape and switching to a different file work. Closing, reconfiguring, removal, replacement and superseding requests invalidate old results. A failed preview cannot interrupt ordinary playback.
3. Verify exact packet and native picture and audio behavior against the complete synthetic reference while denying gaps and tampering. Run the focused race, route and UI cases and the complete app suite in isolation, then independently review the exact candidate and check the existing native installation and live downloader during cutover.

## Design and limits

- Cinema verifies v1 piece hashes from a qBittorrent export read with an 8 MiB decoded-body cap. Use a new bounded strict decoder that rejects duplicate or unsorted keys and noncanonical integers or lengths. Hash the original `info` bytes. For a v1-only source, require its SHA-1 to match the active torrent hash. For a hybrid source, also bind the full SHA-1 and SHA-256 to qBittorrent's separate v1 and v2 info hashes and verify that the active torrent identifier matches the v2 prefix used by qBittorrent. Bind the selected file to the metadata's unique name and size plus its exact offset, piece range and live qBittorrent index. Decline v2-only sources, ambiguous paths and required pieces spanning another real file until those bytes can be independently reconstructed and proved. A declared padding slice may be supplied as zero only when the completed piece matches its expected digest. The last piece may be shorter.
- A lease captures the active playback object and current connection generation. A dedicated abortable GET reader uses only the authenticated connection captured for that lease. It cannot retry against new credentials or reset the ordinary session. Open the contained file once. Take fresh verified states before each set of piece reads, copy and hash the full pieces, then check all admitted pieces again and recheck layout, path and descriptor identity before publication. Use the existing Windows device-zero identity accommodation. Allow unrelated download writes to the same physical file because the immutable copied bytes carry the exact content proof. Do not disclose paths, metadata or digests to the renderer.
- Reuse the lab's incremental index and sample selection design in packaged Node with typed arrays and bounded exact clocks. Use a cancellable worker so indexing leaves the foreground responsive. Limit bootstrap to 8 MiB and individual bootstrap reads to 256 KiB. Limit the index to 1.2 million samples and 32 MiB packed data and source to 64 GiB. Support torrent pieces from 16 KiB through 8 MiB, with at most 24 MiB of distinct full pieces actually needed across opening and scene. At the two-hour lab's 128 KiB piece size, the 41 needed pieces fit in about 5.2 MiB. Return a distinct data-limit status when the full piece copies would exceed the budget. Reject malformed, external-reference, ambiguous or unsupported containers and timing.
- The child reads only immutable copied piece runs at a high-entropy path on a private loopback listener. A finite explicit range must fit one run. An open-ended range ends at the first hole, and a request starting in a hole fails. Bound request count, elapsed time and served bytes. Never wait for missing pieces. Use bundled FFmpeg for one short copy and bundled FFprobe for bounded output proof. Verify exact packet order, sizes, hashes, timing, IDR and audio alignment. Use the output's exact parsed AAC sample table to corroborate the terminal duration when the bundled older FFprobe disagrees. Require exact cadence and coverage across the actual requested playback window. No output is published before proof.
- Send the bounded clip in the authenticated POST response with no-store. The renderer creates its own Blob URL and revokes it when closed, replaced or expired after one minute. On expiry, even if loaded, stop the preview and tell the viewer they can retry. No replay route or reusable media capability is published. On removal and shutdown, cancel and wait until the preview descriptor and child processes close. Cancel from the existing reconfiguration and attachment lifecycle hooks. Hold one slot until underlying cleanup finishes, actively abort network and terminate the worker and subprocesses, and report busy while a superseded attempt drains. Renderer request identity rejects stale async results. Release owned temporary files on each exit and sweep only the dedicated preview staging directory for orphaned output after a crash.
- Reuse the visual language of Scenes. Offer one explicit time field and Preview action for an eligible incomplete attachment after the main picture has presented. Show the exact target and explain missing data in plain language. A single inline video card handles Play and Close. The card uses a labeled video, muted default, stable focus, a status region and a short reduced-motion-aware entrance. Escape closes the preview first and returns focus to its trigger. Leaving or hiding the player releases the preview. Enable preview audio only if the main video is paused or muted, and remute if the main video becomes audible. It never moves the main playhead. Existing verified Jump and Scene on Arrival keep their own behavior.
- The lab used an isolated synthetic torrent, independently checked packet and PCM timing, and a reference held back until native preview advanced. Production continues to use the installed qBittorrent daemon as the only owner. Prioritizing missing pieces within that daemon and verifying v2-only or cross-file boundary pieces are later parts of roadmap item 08.

## Integration contract

- `createQbit().sceneReader(signal)` captures the current URL and session cookie inside the factory, and binds the existing config object plus an internal reset generation. It returns GET-only `raw` and `json` operations for `torrents/info`, `torrents/files`, `torrents/pieceStates`, `torrents/export`, `torrents/properties` and `app/preferences` for current temp path resolution. It checks the generation before and after transport, uses the provided signal, declines redirects and ends on 401 or 403. It cannot authenticate, retry or write the shared cookie. The server additionally passes the current `memoryConnectionEpoch` binding into media and invalidates it on reconnect or loss. The existing layout export and 64 MiB fallback behavior remain separate.
- `/api/scene-preview` is a token-authenticated POST with a bounded JSON file/session/time request and an `AbortController` on response close. The result is `video/mp4` bytes with `Content-Length`, `Cache-Control: no-store` and the exact translated seek time in `X-Cinema-Scene-Seek`. Expected failures are JSON. The renderer uses its own fetch with `X-Cinema-Token`, no automatic POST replay, a captured attachment and request counter, and the same 15-second operation limit plus a 2-second response margin. An empty token is acquired before an attempt. A rejected token reports retry and refreshes only for the next explicit attempt.
- Server invalidation hooks cover ordinary prepare, removal, shutdown, connect/disconnect epoch changes and successful rescue or warm attachment changes. The current session object, URL/mode, request order and connection generation are rechecked around async work and publication. Client invalidation uses the existing media destruction, minimize, stop, file selection, reconnect, source removal, disconnected status and visibility hooks. The app asset map serves the new JS and CSS.
- One attempt has a 15-second absolute deadline, with at most four seconds for each qB read and the piece-copy phase, three seconds for indexing and FFprobe, and six seconds for FFmpeg. Terminate cancelled worker and child processes and wait for their close before slot reuse. The worker uses 64 MiB old-generation, 16 MiB young-generation and 4 MiB stack limits in addition to the independent typed-array budget. A copied clip spans at most eight seconds from the selected keyframe and is at most 2 MiB, with at least half a second of proven audio and picture after the target. FFprobe JSON is capped at 512 KiB and 1,600 packets. The private child listener accepts at most 32 GETs and serves at most 64 MiB across repeated reads. Its lifetime is tied to the FFmpeg deadline. Absent data and limit violations are separately projected.

- Compare the packaged Node parser's selected packet positions, hashes and clocks to the two-hour lab and the short signed/unsigned composition and edit fixtures. Exercise malformed, duplicate-key and unsupported profile cases and each independent bound. Reject false state-2 bytes, a flipped piece state, ambiguous metadata, and changed descriptor/path. Verify a short last piece and Windows device-zero path identity.
- Cancel separately during export, index, piece copy, FFmpeg, FFprobe and renderer load. Observe descriptor and process closure, temp cleanup and eventual reuse of the single slot. Test an expiry on each side of its deadline, connection change, stale response, media switch and Windows remove-with-delete. Use a recording mock to assert no torrent mutation, no ordinary prepare and stable foreground session and picture.
- Launch the real Windows WebView2 app against the isolated packaged worker and FFmpeg. Verify a non-IDR target with actual frame timing and decoded audio alignment against a complete reference. Exercise keyboard focus, unavailable data, reduced motion and actual foreground playback. Complete exact review and the full suite. Record the existing app version, qBittorrent process and library count through app status and local process identity before and after cutover, without opening saved credentials.
