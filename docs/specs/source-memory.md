## Implementation boundaries

Keep memory qualification separate from the live Release Passport. Only an explicit ordinary first attach from zero can report. A native foreground picture after a real playing event must agree with the exact active file and preparation. Capture is irreversibly void after manual interruption or recovery.

An opening HLS fragment can start slightly after zero. Accept one automatic alignment before the first picture only when HLS signals a skip over the initial buffer gap and the queued seek lands at that exact target within half a second of zero. Input on the video, a user seek, a second seek, or HLS recovery still voids capture.

The admission is held by the exact daemon session, is available only from its successful fresh prepare response and may be consumed once. Capture and display are fenced by the current connection epoch and preference revision. The report checks the exact selected file against the playback scheduler's current session snapshot and confirms membership in the latest known connected library snapshot. An out-of-band file change can take time to reach these snapshots. This keeps observation off the qBittorrent request path. A saved HLS playback copy is excluded. The complete-file label describes the selected file's download state when preparation began.

Mutations invalidate stale admissions before entering the serial write queue. Store only committed data. Keep damaged bytes when recovering from a corrupted ledger. During connection changes, older snapshots and outstanding preparations cannot publish observations. Legacy saved setups get a stable local scope until an explicit successful reconfiguration. An out-of-band engine change at the same address without an observed disconnect is outside this measurement's identity guarantee.

Verification includes overlapping opt-out or clear and record, duplicate reports, stored history reload, read-only startup, disk failures, alias disagreement, stale profile or removal evidence, automatic reconnection and resumed starts, actual visible Windows playback, keyboard-stable updates and measured command traffic. Native window occlusion beyond browser visibility is a documented limit if Windows supplies no reliable signal.

The ledger uses keyed local identities. Its effective HMAC key changes when the user clears history or successfully configures a connection. Direct and prepared video remain separate in each download condition. Record the first frame clock even if the native playing event follows the frame. The two witnesses must arrive within one second and still satisfy the original visible, ordinary playback guards. A second connection submission is refused while the first is active.

The evidence slot is patched after each result render and accepted settings or state update. Evidence is excluded from the keyed card signature. Clear and opt-out hide the existing slot immediately. The Windows walkthrough checks that the card and open native details persist while their timing data changes.
