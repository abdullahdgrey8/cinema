# Sound Map

Roadmap 29 starts with navigation for sounds authored in the selected subtitle track. Open Scenes & sound in the Windows player, then Sound cues. The audio description capability remains a separate roadmap slice because HLS currently outputs only the first audio stream and an alternate track must be identified and selected independently.

## Viewer behavior

- Label the source as sounds written in the selected captions. Use only a loaded track belonging to the exact active file and existing subtitle revision. The panel can read the selected caption track when its normal display is hidden. Opening, browsing, and closing never toggle subtitles, edit timing, fetch external captions, change playback state or create watched evidence.
- Extract standalone square-bracketed lines that match a conservative English sound vocabulary for effects, environment, music, and audience sounds. Exclude speaker-only labels, translation notes, stage prose, ambiguous bracketed words, unbracketed dialogue and lyric lines. Use browser-decoded cue text and render labels as plain text. A line can be included when authored as a sound on its own line alongside dialogue in the same timed cue. Preserve the original label; do not infer audio from the movie or alter the original cue text used by Watched Dialogue and Scene Finder.
- Apply the active caption offset to original start and end. Drop ranges shifted completely before zero. Clip a range crossing zero to zero without extending its end. Dedupe only identical adjusted range and text. Render chronological results with time, authored label and ready/waiting information. Default to cues whose starts are at or before the current playback position. This is position-based, not a watched-history claim. An explicit Show later cues control exposes later results for this attachment. Reset that choice when the exact active file/track or offset changes. No automatically playing or seeking when filtering or paging.
- Page the list with accessible buttons and visible focus, keep the current position and any selected filter coherent while the video advances, and avoid moving focus or announcing on every playback sample. A cue click or keyboard activation is an explicit jump through the existing revision-bound seek function, only when the player's verified map admits the target. Recheck selection identity, availability, player attachment and revision immediately before seek. Confirm outcome only if the same operation is still current afterward. Use no replacement download, FFmpeg, priority, progress store or custom seek path. Playing or paused state stays as it was.
- Provide distinct captions-needed, loading, no recognized sound cues, no cues up to this position, and temporarily unready states. The captions-needed state opens the existing Subtitle settings for optional manual choice, including a short note that sound cues are often in SDH or CC tracks. Show an explicit limited notice if scan or result budget is reached. Ready or failure status uses one polite region; progress in the player retains its existing controls.

## Integration and bounds

- Keep Sound cues nested in the existing Scenes tools disclosure, with a stable heading and accessible keyboard affordances. Read the same browser-backed original cue list from enrichment on demand and keep its original dialogue/digest tuples, source and revision unchanged. Return an exact active track snapshot with revision, offset and source only after a successful current track load. No extra caption parse or index work in normal playback startup. Do not create another HTML track.
- Build only while the player dialog, Scenes and Sound cues are open. Scan at most 16,384 source cues and 1 MiB of text considered, keep at most 720 unique sound entries, process bounded chunks off the immediate open event, and yield between chunks. Short-circuit obvious non-bracket cues before creating a browser fragment. Bind a scan to the exact loaded element, file and revision. Cancel it on close, attachment or offset change; keep a completed bounded index only for the same revision. The page contains at most 10 cues. A time update may change the visible sample but must not replace a focused still-visible button.
- Reuse the current playback-map readiness and seek functions. Do not block or rerun the conversion. A stale asynchronous jump result must not announce or focus a new attachment. Default motion is short and respects reduced motion, with no continuous animation.

Verify keyboard interaction, before-and-after paused seek, a track offset update and replacement, no unauthorized jump on an unavailable HLS range using deterministic playback-map seam, accurate explicit future toggle, 360 px reduced motion, normal subtitle display and Watched Dialogue history unaffected by Sound Map viewing. ### Exact lifecycle

Capture original cue rows from the current loaded track only when Sound cues is open. A revision handle binds hash/file, the exact element and the existing Scene Finder revision. Recheck that handle before each yielded scan chunk and before publication. Cancel without storing partial output if a revision changes or a parent disclosure or the player closes. Cap both raw and decoded string processing, and report partial results after a budget limit. A same-revision completed result may be reused only in the same active player.

During a seek in progress, keep the last confirmed non-seeking position or withhold the list if there is none. Update the default view at the new settled position. Unknown and temporarily unready ranges do not allow a jump. If a focused item disappears after a confirmed backward move, restore focus to the list heading or last stable navigation control. Superseded jump completions report nothing. Existing title/episode retention, qBittorrent streaming and subtitle visibility remain on their normal paths.

F-LINES. Add one read-only enrichment sound-track accessor. It returns existing subtitle revision, exact track element and hash/file identity, original offset, and existing cue tuples only if the exact element and file are loaded. It never invokes watchedCaption or copies the flattened tuple text. The scanner reads tuple[0].text for an inexpensive opening-bracket check, then uses tuple[0].getCueAsHTML().textContent for browser-decoded line boundaries and tuple[1]/[2] for original times. Capture the handle and check its revision, file and element during every chunk. A fixture compares caption playback/digest inputs before and after browsing.

F-LIFECYCLE. An effective visibility predicate requires all three to be open: player dialog, Scenes details, nested Sound cues details. Drive it via listeners for both details toggle events, dialog close and a dialog open-attribute observer (including restored/reopened dialog), and an inexpensive readiness refresh when the existing playback-map signature changes. Abort an unfinished scan and suppress work and stale announcements while hidden; a completed same-revision result can be reused. Escape closes the nested Sound cues first when both disclosures are open and restores its summary focus. A second Escape retains the existing Scenes behavior. Tests cover ancestor hide and modal restoration, even when nested open stays true.

F-GRAMMAR. Match a complete decoded line wrapped in one pair of square brackets. Reject hard-wrapped and multiple-label lines, extra dialogue on that line, colon speakers, digits, URLs, lyrics/music-note glyphs and words outside the supported grammar. Trim and collapse inner whitespace. Preserve case in the displayed label and in dedupe. Cap labels at 80 characters and match English case-insensitively using a short list of known sound phrases and at most two known modifiers. Accepted examples: [Door slams], [Knocking], [Applause], [Distant sirens], [Music], [Thunder], [phone rings], [glass breaks], [footsteps], [wind howls], [laughter], [upbeat music playing]. Rejected examples: [MARA], [MAN:], [whispering], [Music video], [Door slams before Mara falls], [Door slams] Wait, [Footsteps] [Knocking], [door 2], [https://example.com], and ♪ a lyric ♪. The effect vocabulary may add similarly narrow complete phrases. Discard adjusted end<=0 or end<=start after clipping and rounding to milliseconds. Dedupe exact normalized label and adjusted start/end.

F-PAGE-FOCUS. Page the chronological list of currently eligible cues in groups of ten and initially show the latest eligible group. Hold a page anchor by its first stable cue key (adjusted range and normalized label). New eligible cues do not navigate away from that page. Use native Tab, Enter and Space. Keep a focused row button if it remains visible, and return to the stable list heading if a confirmed backward seek or explicit scope change removes it. Totals, pages, controls, accessible names and notices in the default scope expose only the default eligible list, never the number or text of later cues. The Show later cues button has a static label. No transient future update while video.seeking.

F-SUPERSEDE. Each user jump captures an operation token, rendered revision and track handle and active playback identity (generation and URL). Before calling seekScene and after completion require the same operation, exact identity and effective visibility. Only a confirmed true result may announce a jump. A false, thrown or superseded result silently returns to current readiness. No success or old text can appear on a different file or hidden panel. No independent pending seek, pause, play or write to the video clock.
